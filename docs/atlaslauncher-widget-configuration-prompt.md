Реализуй повторную настройку Android-виджетов в AtlasLauncher на Android 11.

Репозиторий: /Users/wital/dev/AtlasLauncher.
Перед правками прочитай применимые инструкции и проверь git status: в рабочей копии
есть незакоммиченные изменения, в том числе HomeActivity.java и README.md.
Сохрани их; не откатывай, не перезаписывай и не включай чужие изменения в свой коммит.

Нужное поведение:
- В обычном режиме рабочего стола никаких дополнительных кнопок на виджете нет.
- В режиме «Редактировать рабочий стол» у системного виджета появляется кнопка
  «Настроить», только если AppWidgetProviderInfo.configure != null.
- Нажатие открывает объявленную провайдером Activity настройки и передаёт ID именно
  этого уже размещённого виджета через AppWidgetManager.EXTRA_APPWIDGET_ID.
- После «Готово» или «Назад» пользователь возвращается в редактирование HOME.
  Существующий виджет сохраняет ID, позицию и размер; новый экземпляр не создаётся.
- Если Activity настройки недоступна, покажи сообщение, не удаляя виджет.
- Настройка встроенных часов, перемещение, изменение размера, удаление и обычные
  нажатия на содержимое виджетов должны продолжить работать.

Где менять:
app/src/main/java/com/mmwtl/atlaslauncher/HomeActivity.java.
В addWidgetEditControls(...) кнопка настройки сейчас создаётся только для часов
(info == null). Добавь общий путь для AppWidget с ненулевым info.configure.
Для запуска используй стандартный AppWidgetHost.startAppWidgetConfigureActivityForResult
либо ACTION_APPWIDGET_CONFIGURE с явным provider.configure.
Не привязывай реализацию к пакету AtlasAppWidget: она должна работать для любого
провайдера, объявившего Activity настройки.

Критически важно разделить первичную и повторную настройку:
- configureWidget(...), CONFIGURE_WIDGET, pendingWidgetId, finishAddingWidget()
  и cancelPendingWidget() сейчас обслуживают добавление нового виджета.
- Для настройки существующего экземпляра нужен отдельный request code.
- Ни RESULT_OK, ни RESULT_CANCELED этого запроса не должны вызывать
  finishAddingWidget(), cancelPendingWidget() или deleteAppWidgetId().
- Учти восстановление Activity: возврат из настройки не должен случайно переключать
  повторную настройку на сценарий добавления нового виджета.

Со стороны AtlasAppWidget контракт уже подготовлен в рабочей копии
/Users/wital/orca/workspaces/AtlasAppWidget/widgetkit:
- package/provider: com.mmwtl.atlasappwidget/.AtlasAppWidgetProvider;
- android:configure="com.mmwtl.atlasappwidget.MainActivity";
- widgetFeatures="reconfigurable|configuration_optional";
- MainActivity принимает ACTION_APPWIDGET_CONFIGURE и EXTRA_APPWIDGET_ID;
- «Готово» возвращает RESULT_OK и исходный EXTRA_APPWIDGET_ID;
- «Назад» возвращает RESULT_CANCELED; настройки общие и применяются сразу;
- постоянная шестерёнка и зарезервированная под неё полоса 40 dp удалены.
На Android 11 не полагайся на автоматическое появление системной кнопки из-за
widgetFeatures: кнопку в своём режиме редактирования должен предоставить HOME.

Проверки:
1. Собери и проверь AtlasLauncher по правилам репозитория.
2. На Android 11, 1440×1920, используй свежий debug APK AtlasAppWidget из указанной
   рабочей копии. Устанавливай обновлением, не стирай данные при конфликте подписей.
3. Проверь отсутствие кнопки вне редактирования; в редактировании она есть у
   настраиваемого виджета и отсутствует у провайдера без configure.
4. Открой настройки существующего AtlasAppWidget, измени сетку/подписи, нажми
   «Готово»; повтори с «Назад». Проверь неизменность ID, числа экземпляров,
   позиции и размера. Для двух экземпляров проверь передачу правильного ID.
5. Отдельно проверь первичное добавление: «Назад» отменяет только новый экземпляр,
   «Готово» добавляет ровно один. Не сломай этот путь повторной настройкой.
6. Проверь настройки часов, resize/drag, клики по ярлыкам и crash log.
